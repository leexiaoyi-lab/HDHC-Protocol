# Safety / Misuse Reporting

Use the **Protocol Misuse / Safety Concern** issue template for non-sensitive concerns.

For public, reproducible findings, benchmark results, counterexamples, and non-sensitive protocol concerns, please use the GitHub issue templates so the evidence can be reviewed openly.

## Private / embargoed / sensitive reports

For sensitive information, do **not** publish personal identifying details, private allegations, exploitable vulnerabilities, embargoed evidence, credentials, private keys, or other material that would create unnecessary risk in a public issue.

Private contact:

**hdhc.protocol@outlook.com**

Use this channel when the report cannot safely be made public at first contact.

Please minimize disclosure to what is necessary for triage. When possible, include:

- the affected HDHC version, release, or commit;
- a concise description of the concern;
- whether the issue is reproducible;
- the smallest safe reproduction steps or evidence needed to understand the issue;
- whether any part of the report is embargoed or should remain confidential.

Do not send passwords, API keys, authentication tokens, private keys, or unrelated personal data. Redact sensitive material unless it is strictly necessary to evaluate the report.

A private report may later be converted into a public issue or reproducible benchmark case only when doing so is safe and appropriate.

Examples of relevant concerns:

- a rule that predictably exposes victims to renewed danger;
- a benchmark case that contains private real-person data;
- a loophole that allows “greater good” reasoning to justify arbitrary coercion;
- systematic bias that exempts powerful actors;
- a return-path rule that recreates the original harm channel.
